# 错误处理

| 情况 | 行为与处理 |
|---|---|
| Docker 命令不可访问 | 先区分未安装、PATH 未包含客户端和当前终端权限限制；不自动重复安装 |
| Docker 只有客户端无 daemon | OCI 构建 BLOCKED；先确认用户选定引擎已可运行，不拿 WSL2 venv 当容器 |
| build 工作区 dirty | 先审阅并提交 runtime 自有文件；不处理原项目 dirty 文件 |
| 原码/归档/wheel 哈希不符 | 立即拒绝；保留下载及错误，不替换锁或放宽检查 |
| source 中出现缓存 | 禁止字节码与 pytest cache；用新的固定归档提取目录，不放开 evidence |
| 非 root 挂载权限失败 | 保留失败；修复本次输出目录 ACL/所有权，不使用 privileged 或挂载整个磁盘 |
| 内存未知/不足 | BLOCKED、退出 3；释放自己可控任务或选资源充分主机，不杀其他进程 |
| 共享锁占用 | 拒绝并发；等待已运行任务，不删除锁文件来绕过 |
| 子程序失败 | 停止本 task 后续命令，保留日志及原退出码 |
| 分类输入缺失/被改动/身份不兼容 | 拒绝分类；显式完成缺失阶段，不用冻结结果补齐 |
| 中断 | 向本次子程序组发送停止信号，保留已写出的检查点与日志；完整 L4 中断行为待实测 |
| 数值结果不合格 | 保留 FAIL；检查依赖、协议与资源，禁止调整科学容差来获取 PASS |

原七任务的 Docker 底层入口为 `run-docker.ps1`；Windows PowerShell 5.1 可通过 `start-runtime.ps1` 调用已有 PowerShell 7.3+。五个 P14 资格任务的本轮 Runtime 修订在子程序退出 0 但门槛失败、未知或缺失时返回 4；真实子程序非零退出保留其错误码。历史镜像必须同时检查 manifest，不能仅凭 exit 0 判定数值通过。

新普通、固定和专题服务在科学 worker 前检查输出目录实际可写性。只修复新建专用输出根对宿主用户及 UID 10001 的权限，不用 `chmod 777`，也不更改原科研目录。Docker 创建超时不等于没有创建容器；身份无法闭合时保留隔离记录和活动锁，不能删除未知或其他任务容器来绕过。

运行目录从不自动清理。检查点写入由上游控制：第一次写出前中断可能没有检查点；有检查点也不表示可恢复优化。
