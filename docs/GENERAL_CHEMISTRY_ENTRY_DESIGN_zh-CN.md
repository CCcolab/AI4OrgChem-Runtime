# 面向用户分子的本地化学计算入口设计

2026-10-08，定位修订0.1。依据用户要求：Runtime应作为通用化学计算平台，用户不必了解专著P01—P14。本文件确定下一步实施方向；新增通用任务尚未实现或验收，不改变此前固定案例交付的身份、规则或结果。

## 1. 产品入口

用户的主要流程是：**准备自己的分子 → 选择计算目标和方法 → 检查输入与资源 → 本地执行 → 查看和保存结果**。

主页、帮助和任务菜单以化学操作命名。用户运行普通计算无需选择P编号、阅读专著、划分专有两片段或确认条件态协议。方法、单位、参数和限制直接在相应计算任务中说明；详细版本、来源与科学论证放在结果详情中按需查阅。

P01—P14继续作为历史科学案例和平台回归材料，放入“示例与验证”。内部案例ID和证据映射保持，不重写历史、不把改名当作功能升级。已交付P02表统计、P13固定图/账本及乙烯P01控制是三个固定示例；其中统计和图账本不等于任意用户数据或分子服务。

“通用”落实为可处理用户提交的、落在公开支持范围内的分子及标准计算任务。每个任务独立说明方法、输入范围和验收状态，逐项扩大支持。

## 2. 功能目录与当前事实

| 用户看到的功能 | 用户提供什么 | 用户获得什么 | 当前Runtime状态/实施顺序 |
|---|---|---|---|
| 分子输入与资源检查 | 分子结构、单位、电荷、多重度、任务 | 原子映射、电子数、输入错误、资源预估与准入状态 | 旧Check只覆盖受限C/H、平面、两片段请求；须建立新通用请求和检查器，优先实施 |
| 单点能量计算 | 自己的XYZ结构、受支持方法和基组 | 总能量/单位、SCF收敛及诊断、分子与方法身份 | 固定乙烯RHF控制和历史内部普通态有记录；通用单点服务尚未开放，首批核心 |
| 轨道与电子密度分析 | 合格普通单点结果；明确的分析选项 | 占据、轨道能级、系数、密度、可选局域化及残差 | 固定乙烯Boys/PM同态控制通过；须增加用户结果分析/导出，随后实施 |
| 分子图与常用描述符 | 带可靠键连接的SDF或SMILES等 | 分子式、图信息及标明定义的描述符 | 已有真实RDKit固定图示例；通用图输入、键/立体化学检查及描述符服务待适配 |
| 几何优化与结构变化 | 用户结构、方法、约束及预算 | 优化轨迹、梯度/位移门槛、终止原因和最终结构 | 旧固定案例有记录；通用优化未开放，在单点/导数及优化依赖验收后实施 |
| 扫描与结果比较 | 可追溯结构集合、统一方法、扫描坐标或比较目标 | 能量曲线、各点资格、同条件比较和失败点 | 通用入口待实现，基于前述合格任务逐步增加 |

化学键与电子结构研究作为轨道、密度、结构和能量分析的应用场景呈现；数值模拟输出及其方法近似不宣称实验微观测量。特定耦合删除/屏蔽态比较作为项目特色专项，在普通计算目录之外列明条件定义和资格。

## 3. 拆分普通计算与条件态比较

现有`schemas/user-molecule-request-v1.json`要求固定`user-molecule-fixed`服务、两片段、条件定义确认和特定计算profile。`runtime.user_molecule`的Compute执行普通态与专有条件态比较，现有profile整体关闭。它不适合作为普通单点任务的通用请求。

下一步新增独立的通用任务命名空间和请求版本，例如`single-point`、`orbital-density`、`molecule-properties`；这些是设计名，当前不可用命令。请求核心字段为：任务、结构文件/格式/单位、电荷、多重度、受支持的方法/基组、资源预算。记录保留原子顺序与转换映射，不静默加氢、重排、旋转或修改用户结构；XYZ本身不提供可靠键阶，图任务须明确输入连接信息及其来源。

普通单点结果不要求用户提供专有片段规则，也不自动执行条件核。轨道分析绑定一个合格普通态结果；局域化属于指定占据空间的表示变换，不自动生成化学稳定化分类。

三个状态独立登记：

- **普通态单点服务**：`NOT_IMPLEMENTED_AS_GENERAL_USER_SERVICE`，实现及验收后逐profile开放。
- **用户分子条件态比较**：`BLOCKED`，旧门槛、失败记录及预算全部保留。
- **优化/扫描等扩展服务**：按各自实现、依赖、导数及资源验收记录独立开放。

不把“底层计算库已有功能”写成“Runtime已经交付该服务”；不使用固定乙烯通过记录替代其他分子资格，也不直接将旧`compute_enabled`改为true。此定位修订没有开放任何新科学执行。

## 4. 复用成熟计算生态

普通HF/DFT继续采用PySCF；其官方SCF文档说明HF及Kohn–Sham DFT能力。Runtime承担输入、调度、资源与输出合同，不另造普通SCF算法。[PySCF SCF文档](https://pyscf.org/user/scf.html)

分子图与描述符优先复用RDKit，并核对显式氢、价态、键阶和立体信息，分别记录解析失败和不支持项。[RDKit使用文档](https://www.rdkit.org/docs/GettingStartedInPython.html)

几何优化可采用PySCF的geomeTRIC/PyBerny等接口。它们的安装、版本、许可证、导数及优化端点须另行核查；当前镜像依赖锁未提供这些优化器，故不能沿用固定任务Docker结论宣称通用优化已支持。[PySCF几何优化文档](https://pyscf.org/user/geomopt.html)

分子、任务与结果字段参考已有QCSchema设计思想；正式字段映射和适配另行审查。本地首批不部署服务器、云调度、训练或预测平台。

## 5. 首批实施与验收

暂按“普通量子化学优先”推进，等待用户对首批任务优先级的选择。首先交付用户XYZ的普通单点与对应轨道/密度结果，采用已锁定计算库；先冻结受支持的元素、电荷/自旋、方法/基组、nAO上限和预算。RHF闭壳层可作为第一计算profile，DFT和开壳层分别适配及验收。具体支持清单和真实执行预算在实现前形成可审阅合同，不沿用只允许固定乙烯的验收授权。

1. **任务/输入合同**：建立新请求和服务状态登记；用户提供分子而非P编号；不依赖旧条件片段、平面或xy定向规则。版本固定、方法/基组白名单、电子数/多重度相容性、有限坐标/单位、碰撞和资源拒绝具有独立测试。
2. **普通单点适配器**：仅调用选定PySCF普通方法；持久记录调用预算、输入哈希和结束状态。超时、OOM、未收敛、缺失尾检不能产生合格结果；无静默重试或更换方法。
3. **轨道/密度与导出**：结果保留能量账本、电子数、占据、诊断及明确单位；导出数组/报告与原结果绑定。局域化检查占据空间、密度和能量不变性，解释属于同态表示分析。
4. **真实小体系验证**：至少覆盖含H/C/N/O及三维非平面的代表分子，如水、甲烷、氨与乙烯；采用冻结几何和方法。这些是拟验收对象，尚未计算。对请求以直接调用同版本PySCF、同方法/设置核对适配器一致性；该对照是包装一致性验证，不冒称独立科学实现认证。数值门槛预先冻结，不因结果失败放宽。
5. **完整交付验证**：检查非root、只读输入/源码、网络关闭、内存/CPU/墙钟、退出码及删除容器后的输出保留。分别记录工程、数值和运行范围。用户能以自己的合格请求完成一次计算和结果下载/导出，不需要读专著或填写P编号。

新普通态任务有独立科学目标和验收合同；旧条件核的规则、正能隙/固定点门槛及旧失败记录保持。收敛、可报告数值与稳定性分别说明，不把普通SCF收敛自动解释为稳定极小态。
