## 1. 三个入口与共同服务

| 入口 | 面向用户 | 拟提供能力 | 当前边界 |
|---|---|---|---|
| GitHub | 开发者、审阅者 | 源码、协议、测试、来源锁、反馈与版本固定的 Notebook | 新草稿与 Notebook 未公开；公开范围和推送仍另行确认 |
| Colab Notebook（后续可选） | 自愿使用云端交互入口的用户 | 恢复实施后教学、请求准备、检查、记录判读；实测后小体系技术计算 | 当前暂缓，不要求专业用户使用，不阻塞本地交付；未来独立验收 |
| 本地 Docker | 需要受控环境的专业用户 | 已验证任务的执行、账本和运行记录；新适配器验收后承接用户分子请求 | 旧七任务与新用户分子分开；旧镜像未包含新增能力 |

当前本地主流程：准备 XYZ → 用模板填写两片段和允许的配置 → 启动器检查 → 执行获准计算 → 阅读简报与保存完整记录。后续 Colab 可提供“打开示例 → 看编号/片段 → 上传 XYZ → 检查 → 计算或导出本地 → 下载”的替代入口。协议详情和源码按需展开。

Notebook 只负责表单、文件选择、显示、调用和下载。输入解析、原子编号、快照、profile、资格、比较量和报告由同一套受版本控制的适配器处理；云端与 Docker 使用一致的服务合同。不得在 Notebook 单元格复制生产 SCF、掩码、J/K 或能量求值逻辑。独立科学参考仍按 A06/A07 独立实现，与生产适配器分开。

## 3. Notebook 的六个操作区

1. **打开与安装**：说明当前开放阶段、云端数据位置和运行限制；显示 Notebook 内容身份、适配器/科学来源及安装结果。初次检查用标准 CPU；不因选择 GPU 就宣称有加速。
2. **选择示例或上传**：只接收限定大小的 XYZ 与严格 JSON，或按表单生成同一 JSON；展示逐原子 1-based 编号、元素、Å 坐标及碳 A/B 归属。三维预览可选，不依赖新分子编辑器。
3. **确认与检查**：简短说明同几何比较、指定 h/S/F 与 ERI 规则、xy 定向及候选体系范围；显示真实回执、拒绝原因和资源判断。用户确认不替代方法审查。检查不分配完整 ERI、不运行 SCF。
4. **运行或转本地**：满足 CB2/CB3 门槛才计算，绑定检查快照；否则导出请求/坐标/profile 身份。Docker 接收后重新检查合同、平台资源和资格，不把 Colab 回执当宿主准入许可。
5. **判读**：两态能量与同几何差值、执行/数值/研究三层状态、方法范围和警告先显示；详细账本与来源按需展开。失败差值为 null；不得用数值接近称方法等价。
6. **下载**：用户主动下载输入快照、回执、JSON、简报、manifest 和已存在日志；附文件大小/SHA-256。没有产生的文件逐项说明，不能补造成功记录。

请求准备不自动加氢、优化、重排、旋转或投影坐标；两个片段仍为碳 π 组，不当作标准分子碎片或自动固定片段电子数。表单字段与严格 JSON 一一映射，缺省/非法输入显式反馈。重复执行单元格要生成独立请求或 run ID，不覆盖上一轮记录，也不重复启动仍在运行的作业。

## 4. 安装、身份与共同合同

- 发布时固定 Notebook 内容/文件哈希、实际仓库与完整 commit SHA；安装固定适配器制品、科学来源、schema/profile/规则及依赖锁。下载核对大小和 SHA-256，版本不匹配停止；不能静默切换 main/latest 或换 PySCF 版本。当前实际 GitHub owner/路径、Notebook 文件名、制品 URL 和新提交均待确定，不生成虚假“Open in Colab”链接。
- 安装方案候选为受版本控制的 Python 制品及明确的依赖安装清单；具体 wheel/源码包、Python/ABI 和原生数值库须先验证。沿用科学合同 PySCF 2.14.0；Colab 当前 Python 若不兼容，记录具体版本及错误为 BLOCKED，不升级原项目环境或改锁换取通过。
- Notebook 与 Docker 共用科学适配器和相同输入/结果合同；各自有平台执行封装。Docker 的容器身份在非容器 Colab 执行中写 null 并说明不适用，另记实际软件制品/文件身份、Python/OS、CPU/内存、数值库和有效线程。身份未知写 UNKNOWN，不能填旧 image ID。
- 安装/下载和计算阶段分开留存命令、网络需求及结果。计算逻辑不在线更新源码/基组、不自动上传数据；这不证明托管 VM 严格断网。Docker 的非 root、只读根文件系统、--network none、容器删除后持久性按 A12 单独验证，不作为 Colab 保证。
- CB0 读旧记录时保留原 run/image/科学来源身份，不用 Notebook 身份替换它们。现有记录缺少新合同字段时写缺失/不适用，阅读摘要另有生成身份，不回写原记录或认证新数值资格。

## 5. 资源、不完整运行与数据位置

[Colab 官方 FAQ](https://research.google.com/colaboratory/faq.html)说明资源和使用限额会变化，会话可能终止；分享 Notebook 包括代码和输出，运行 VM 并不随之分享。这决定入口须有真实资源检查、用户导出和明确的失去运行环境边界，不能承诺固定核数、固定内存或持续运行时长。

CB2 只启用已冻结的 pilot profile、受测 nAO/规模和单任务预算。读取实际可用内存/进程限制、CPU/线程、已用空间；按 A11 已校准峰值及余量检查。无法可靠取得条件或不足时拒绝计算，可继续准备请求。max_memory 只是程序建议，设置线程数也不是 CPU 配额；不得把这两项当硬限制。

计算在独立子进程执行，验证内存上限/超时/取消能力与实际生效值；Notebook 主进程作为同一 VM 内监督者，先落盘 run ID/快照/启动记录，按保存的进程组取消。无法可靠限制或校准时保持 CB2 BLOCKED。故障试验在小型受限子进程中执行，不压满云端 VM；浏览器断连不自动等于计算取消。

整个 Colab VM 被收回或重置时，同一 VM 内监督者和文件也可能消失，不能承诺写出最终退出码/OOM 原因或保留结果。运行前提供输入与启动记录的主动下载；运行后及时导出。缺失结束记录时，在平台 manifest 扩展中记 termination_status=UNKNOWN、终止原因 UNKNOWN；execution_status 只保留最后可确认的历史观察（例如 RUNNING），注明不能据此断定当前仍在运行。比较不可用，不伪造 FAILED/COMPLETED 或 0 退出码，不向科学状态枚举暗增 UNKNOWN。任何已导出的旧摘要作为独立证据保留，不能凭重新连接恢复原科学运行。

XYZ、请求和日志由用户显式上传到自己的云端会话，入口不自动挂载 Drive、不访问其他云盘、不发送给项目维护者或外部分析接口。简短提示说明 Notebook 输出保存/分享可能披露分子与结果；机密研究数据可转本地入口。导出默认主动下载，若未来增加 Drive 保存，单列用户选择与验收，不作为首批持久性保证。

[Colab 官方本地运行说明](https://research.google.com/colaboratory/local-runtimes.html)支持连接本地执行环境；这一模式另有配置和权限，不等于本项目候选 Docker 已可直接连接。首批采用“导出请求 → 本地 Docker”，不自动开启 Jupyter 服务、端口或本机连接，不拉取官方演示镜像冒充项目镜像。
