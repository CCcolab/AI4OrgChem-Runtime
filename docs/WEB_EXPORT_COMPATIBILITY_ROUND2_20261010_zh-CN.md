# 网页导出、参数说明与 QA 统计修订

本轮针对 `a2c071f` 的三项反馈，只修改网页及其生成材料。科学代码、输入、计算命令、门槛和资源合同均保持原身份；未执行科学计算、镜像重建或 WSL 升级。

## 下载相容性与证据边界

外部审阅报告中的 HTML 与 ZIP 下载在 `EXPORT_SOURCE:INCOMPLETE` 被拒绝，解析后的四项自有头部元素均未识别。这是外部失败记录；原审阅环境的源快照头部是否完整仍未知。本地 Edge 的上一轮成功记录原样保留，本轮不将它改写为所有浏览器通过。

修订先检查保留快照本身，再分别记录序列化标记和解析结果。正常解析与兼容解析都必须取得完整的 UTF-8 编码、视口、标题和非空自有样式，并与原快照逐项一致。兼容路径重新解析同一段 HTML，不从预期对象补写任何缺失的头部元素；两条路径都失败时仍停止下载。

包外验证 JSON 增加 `export_diagnostics`，区分快照生成、快照解析、组装和序列化复读。完整性错误不再笼统提示下载权限。另提供已核验部署文件的静态 HTML／ZIP 入口，供动态导出受限的浏览器取得指南；这些文件的身份仍须按当前记录核对。

本地应用内浏览器的实测包括：

- 正常 HTML 和 QA JSON 下载成功。
- 模拟 DOMParser 丢失全部四项头部元素时，兼容路径的 HTML、ZIP 和 QA 下载成功；HTML 与正常路径逐字节一致。
- 模拟 DOMParser 丢失头部且兼容解析丢失自有样式时，明确拒绝导出，未补造样式。
- 最终 ZIP 已实际下载，十个成员的 CRC、安全目录及哈希检查通过；包内 HTML 与仓库正文一致。

以上是本地正常环境及合成故障夹具的验证，不证明它们就是原审阅浏览器的根因。原审阅环境的新修订复测、真正 200% 缩放及完整键盘导航仍未执行。

## 参数与统计

固定专题和高成本说明改用新安装 Python 入口的 `--inputs`、`--task`、`--mode`、`--budget`、`--output-root`、`--installation-record` 和 `--docker-executable`。旧专项启动器保留自己的参数合同，不能全站机械替换。

专题卡 QA 改为识别真实的 `--mode` 参数，实际下载 JSON 中恢复为 ledger 8 条、preflight 8 条、live 7 条。这是网页命令清点，不是运行数或科学通过数。本轮 82 个既有带 ID 的代码文本目标与 `a2c071f` 逐字一致。

当前文件身份和具体证据见 [本轮机器记录](../validation/web-guide/export-compatibility-round2-20261010.json)。此前成功记录与本次外部失败记录分别保留，不相互覆盖。
